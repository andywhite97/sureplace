# SurePlace SEO audit — 9 October 2026

Reviewed route metadata, Open Graph/Twitter images, canonical URLs, structured data, indexing policies, sitemap generation, static hosting fallback, and build-time rendering. This is a source and generated-output audit; Search Console access and production crawl/indexing metrics were not available. The public domain and backend sitemap could not be retrieved through the web tool, so their deployed status is unverified.

## Fixed

| Finding | Change |
| --- | --- |
| Agents directory and public agencies could retain metadata from the preceding route | Added route descriptions, clean canonical URLs, social images and agency structured data. Filtered agent searches use `noindex,follow`. |
| Agent profiles used a generic sharing image and called unverified professionals trusted | Use the avatar or agency logo, add Person structured data and remove the unsupported trust claim. Unavailable profiles clear stale metadata. |
| Help, About, Pricing and legal pages were client-rendered | Include these public pages in build-time prerendering. Public agent IDs and associated agency slugs are also discovered from the paginated public agent API. |
| Private child pages could inherit metadata or miss a policy of their own | A router title strategy applies private metadata to account, staff, auth, invitation, messaging and booking checkout routes. Private canonical URLs exclude query parameters. |
| Generic router titles could overwrite public titles applied during activation | Public components keep ownership of their SEO titles; the route strategy only enforces private metadata. |
| The build skipped property discovery after a 3.5-second API timeout | Allow up to 15 seconds per discovery request and retry once before the existing client fallback. |
| Robots referenced a backend host different from the configured production API | Point robots to a same-origin frontend sitemap generated during GitHub Pages preparation. |
| The static 404 fallback copied the homepage's indexable metadata and canonical | Make fallback HTML `noindex,follow`; remove homepage canonical and JSON-LD. The app still loads when the fallback serves a client route. |
| Robots blocked login/register crawling, hiding their `noindex` tags | Allow crawling so search engines can read the exclusion tags. Account access remains protected by guards and backend permissions. |
| Backend sitemap omitted public information and professional pages, and claimed static pages changed on every request | Include public information, active agents and active agencies; omit fabricated static `lastmod` dates. |

Cover-image selection, absolute uploaded media URLs, gallery/default-image fallback, image alt tags, detail retry metadata, property descriptions and detail JSON-LD were improved in the preceding pass. Canonical search filters, production/development indexing separation and listing breadcrumb data were already present.

## Remaining launch work

1. **Deploy the generated Pages artifact and backend changes.** Confirm the production `robots.txt`, same-origin `sitemap.xml`, cover-image URLs, and initial HTML after deployment. Submit the frontend sitemap in Search Console and inspect representative listing URLs. Local verification cannot establish Google's indexing status.
2. **Keep listing HTML fresh.** New listings and changed cover images require a frontend rebuild. API failures during prerendering fall back to client rendering, and those URLs are deliberately absent from the generated frontend sitemap. Check build discovery warnings before release. Consider a publication-triggered rebuild or runtime rendering if listings change frequently.
3. **Independent agencies need a discovery source.** Agencies attached to a public agent are prerendered. Active agencies without public agents remain client-rendered; they appear in the backend sitemap. A public agency list endpoint or a build-time feed would allow all active agencies to be prerendered.
4. **Measure production performance.** The build still reports existing initial-bundle and component-style warnings. Run mobile PageSpeed Insights/Core Web Vitals on real property and stay pages after deployment; this audit did not measure field performance. Keep hero images sized/compressed and reserve their layout space.
5. **Static search pages have limitations.** Location/type search query variants get metadata in the browser, but static hosts serve the base page HTML first. If location searches become a main organic acquisition channel, provide prerendered location URLs with useful local content. No ranking improvement is guaranteed by metadata alone.
